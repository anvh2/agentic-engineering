## 2. Gemini CLI 0.63.0 vs Codex: what is different (inspected, not assumed)

Sources: `gemini --help`; the docs bundled with the install (`headless.md`, `sandbox.md`, `trusted-folders.md`, `policy-engine.md`, `configuration.md`); the shipped Seatbelt profile and default policy TOML files; and the bundled JavaScript where the docs were silent or contradicted each other (live behaviour was taken over the docs in every conflict). No credential file was opened.

| | Codex adapter | Gemini adapter | Consequence |
| --- | --- | --- | --- |
| Headless | `codex exec ... -` | `gemini --prompt <text> --output-format stream-json` | Output is JSONL: `init` (reports the model), `message`, `tool_use`, `tool_result`, `result` (`stats.input_tokens` / `output_tokens`). |
| Prompt delivery | stdin via trailing `-` | stdin **plus** `--prompt` (stdin is prefixed to it) | Adapter sends a fixed one-line stub in `--prompt`, the task on stdin. **Inside `--sandbox` the CLI relaunches itself and moves the stdin text onto the child's argv** (visible in `ps`; OS argument limits). The adapter refuses prompts over 100,000 bytes. |
| Working directory | `--cd <dir>` | none; the process cwd | The adapter spawns it with `cwd = worktree`; that same directory is the Seatbelt writable root. |
| Sandbox | `--sandbox workspace-write` (built in) | `--sandbox` = macOS Seatbelt profile `permissive-open`, or Docker/Podman elsewhere | Only Seatbelt is accepted. Any other platform, or a `sandbox-exec` that does not run, makes the provider unavailable (nothing starts). |
| Approvals | `exec` never asks | headless **denies** anything that would ask; `--approval-mode auto_edit` auto-allows edits | Never `yolo`, never `default`. |
| Network tools | off by prompt | `auto_edit` **auto-allows `web_fetch`**; default policy allows `google_web_search` | The prompt cannot be the control. A per-run **admin policy** denies every tool except the file tools. |
| Ignore operator config | `--ignore-user-config` | **no equivalent**; the system-settings layer is ignored unless root owns its directory | Replaced by a private `GEMINI_CLI_HOME` (section 3). |
| Sign-in check | `codex login status` (exit status) | none | Probe reports sign-in as *unchecked*. A signed-out CLI fails at run time with exit 41, before any model request. |
| Cost / quota | not reported | not reported (tokens only) | `costUsd` and `quota` are `UNKNOWN`. |
| Model | not reported | the `init` event names it | Recorded as observed when none is configured; else `UNKNOWN`. |

## 3. Safety design

Five independent layers, each enforced from outside the model. Where one fails, the next still holds, and the runner's filesystem comparison decides PASS regardless.

1. **Fail-closed preconditions** (no process starts otherwise): `gemini --help` must advertise `--prompt --sandbox --approval-mode --output-format --admin-policy --allowed-mcp-server-names --skip-trust`; `sandbox-exec` must run; the worktree must not contain `.gemini` or `.env` (lstat, so a dangling symlink counts); the prompt must fit; `passEnv` may name only credential variables (`GEMINI_API_KEY`, `GOOGLE_API_KEY`, Vertex variables, proxy variables), and never `SANDBOX`, `GEMINI_SANDBOX`, `SEATBELT_PROFILE`, `GEMINI_CLI_*`, `GOOGLE_*_BASE_URL`.
2. **Command**: an allowlist of eight switches; approval mode must be exactly `auto_edit`; `--sandbox` must be present; `--model` must be a plain name (cannot smuggle a flag). Verified against the real CLI's own strict parser (section 6).
3. **Private home** (replaces `--ignore-user-config`): each call gets `GEMINI_CLI_HOME=<tmp>/agentic-gemini-XXXX/home`. The operator's `~/.gemini` (settings, hooks, MCP servers, extensions, user policies, `GEMINI.md`, cached sign-in) is never read. The settings file inside it is the only user-level configuration: `tools.core` allowlist (7 file tools), `tools.sandbox`, hooks off, skills off, no usage statistics, `model.maxSessionTurns: 25`, `security.disableYoloMode`, `advanced.ignoreLocalEnv`. Removed after the call, including after cancel.
4. **Admin policy** (`--admin-policy <dir>`, highest tier): deny `*` at priority 100, allow the read tools and (in `autoEdit`) `write_file`/`replace` at 200. Shell, web fetch/search, MCP, skills, sub-agents are denied here and absent from `tools.core`.
5. **Runner authority**: any change outside `allowedFiles` is a forbidden mutation (tree restored, task fails); a changed git HEAD fails the call; PASS only from the sandboxed verifier.

Budget and process control are the Codex ones: `limits {maxRuntimeRetries: 0, maxCodingAttempts: 2}`; no fallback to any other provider (the registry has none); cancel, timeout and the per-call deadline end the CLI's process group (SIGTERM, then SIGKILL), and a CLI that cannot be confirmed dead keeps the call pending so the `gemini` permit stays held.

### Findings during the work that changed the design

| # | Finding (how found) | Consequence |
| --- | --- | --- |
| 1 | The CLI **silently skips** the system settings file unless its directory is root-owned (printed "Skipping system settings file ... not owned by root", then carried on). Found by running the real CLI on the first design. | A per-run `GEMINI_CLI_SYSTEM_SETTINGS_PATH` would have been ignored without any failure. Replaced by the private home. A test asserts the variable is not set. |
| 2 | `.env` discovery **walks up** from the worktree to the filesystem root and loads the first file found (bundled code). The project itself has a `.env`, and smoke worktrees live under it. | `advanced.ignoreLocalEnv: true` in the private settings (the home itself has no `.env`). The worktree-root `.env`/`.gemini` check stays as a second layer. |
| 3 | Folder trust is **on** by default here (`mcp list` in a fresh folder: "disabled because this folder is untrusted"), and an untrusted workspace loses auto-approval. | `--skip-trust` is required. It is the documented headless switch; it is acceptable only because the home is private (no trusted-folder list, no user config to unlock) and the worktree is vetted. A conscious, visible trade-off. |
| 4 | `auto_edit` mode auto-allows `web_fetch` (default `write.toml`, priority 15). | The admin policy. A prompt line saying "do not use the network" is not a control. |
| 5 | The Seatbelt profile denies the sandboxed process **reading** `~/.gemini/oauth_creds.json` (observed with a decoy file), and the private home (finding 1) hides any cached sign-in anyway. | Cached Google sign-in cannot work; an API key in the environment is the only authentication. The smoke command requires one. |
| 6 | The docs contradict themselves on folder-trust defaults (`trusted-folders.md` vs `configuration.md` vs two code paths). | Live behaviour (finding 3) was followed. Not relied on being stable across versions: the probe checks the flag set, not the version. |

## 7. Known sandbox limitations (read before running)

1. **Reads are not restricted.** The profile allows reading any file (except Gemini's own credential files); anything the model reads goes to Google. Do not run real tasks where that matters. A `strict-open` profile exists but was not tried (it may break the CLI).
2. **The CLI's parent process is not sandboxed.** It authenticates, reads settings and relaunches itself into the sandbox. Same position as the Codex CLI.
3. **The task text is on the sandboxed child's argv** (process list), capped at 100,000 bytes.
4. **macOS only.** Docker/Podman/Linux are refused, not supported.
5. **Network is open** inside the sandbox (the profile needs it to reach the API). Web *tools* are denied by policy and allowlist; a shell would not be, which is why shell is denied and `run_shell_command` is absent from `tools.core`.
6. **Project instructions can still reach the model**: the CLI loads `GEMINI.md` context files from the worktree upward (prompt influence, not configuration). The fixture has none, and neither does the project root (checked by listing names, not by reading); where the upward search stops was not verified, and the operator's global `~/.gemini/GEMINI.md` is not loaded (private home).
7. **Supplemental admin policy is ignored** if a root-owned standard policy directory (`/Library/Application Support/GeminiCli/policies`) contains TOML. It does not exist on this machine; the allowlist in `tools.core` still applies in that case.
8. **Unproven in a real run** (each fails closed at the cost of at most one invocation): that the CLI runs to completion under Seatbelt with a private home (the profile denies writing `<home>/.gemini`, where it normally keeps session files); that `--skip-trust` is enough for `auto_edit` to apply edits headless; that the admin-policy deny rules and `tools.core` names (`grep_search`, `read_many_files`, ...) behave as documented; that the real `stream-json` stream matches the parser; the exit codes. The parser is tolerant and cannot decide PASS.
9. **Cancellation is verified only with the fake CLI.** The real chain is `gemini` -> `sandbox-exec` -> `sh -c` -> `node`, all in the process group the adapter signals; it is not tested with the real binary (same status as Codex).
10. **`stats.input_tokens` is what the CLI reports** (it may include cached tokens). No cost or quota is known; a pinned model (`AGENTIC_GEMINI_MODEL`, e.g. the CLI alias `flash`) is the only lever on spend.

## 8. The ONE real Gemini HTTP smoke (prepared, **not executed**)

Same fixture, harness and acceptance checks as the Codex HTTP smoke: a disposable Go repo, one task (`smoke-double`: make `Double(n)` return `n * 2`, keep the comments), a dedicated Mastra server the command starts and stops, `go test -count=1 ./...` as the verifier.

**Prerequisite (yours):** a Gemini API key from Google AI Studio, exported in the terminal that runs the command (not typed on the command line, so it stays out of shell history):

```sh
export GEMINI_API_KEY=...      # not printed or logged by the command; only "is it set" is checked
```

**Command:**

```sh
cd /Users/anvh/go/src/github.com/anvh2/agentic-engineering && \
AGENTIC_REAL_PROVIDER_SMOKE=gemini-http \
AGENTIC_ALLOW_PROVIDERS=gemini:smoke-double \
AGENTIC_GEMINI_PASS_ENV=GEMINI_API_KEY \
npm run smoke:gemini-http
```

Optional: `AGENTIC_GEMINI_MODEL=<name or alias>` to pin the model (otherwise the CLI default is used and the model it reports is recorded). There is no OAuth path: with the private home the CLI cannot see any cached sign-in, so an API key is the only way in.

**Refusals (exit 2 or 3, nothing started).** Run by me, each printing the expected message: no opt-in; the Codex opt-in value; no allow-list entry for Gemini; any argument; a `passEnv` name outside the credential list; no API key set. Covered by code and unit tests but not run here: Gemini not `available`, and `go` missing. A Codex allow-list entry never counts for Gemini (unit-tested).

**Allow-list, both processes:** whatever the operator allowed, the command hands exactly `gemini:smoke-double` to the scheduler **and** to the Mastra server's `AGENTIC_ALLOW_PROVIDERS`; the server's `GEMINI_API_KEY` is forwarded because it is named in `passEnv` (the harness forwards only base variables, Go variables and the named ones). For later production use the operator would set `AGENTIC_ALLOW_PROVIDERS=gemini:<taskId>` (or `lead run --allow-provider gemini:<taskId>`) **and** the same in the Mastra server's environment, and the server would need the key forwarded; see section 9, item 1.

**Bounds (enforced by code):**

| Bound | Value | Enforced by |
| --- | --- | --- |
| Objectives / claims | 1 / 1 | command takes no arguments; task `maxClaims` |
| Gemini CLI invocations | **1** | `limitInvocations` inside the server (a second is refused before it starts) |
| Model turns inside that invocation | <= 25 | `model.maxSessionTurns` (exit 53 beyond). The CLI's own API-level retries are **not** counted by this runtime. |
| Automatic runtime retries / fallback | 0 / none | descriptor limits; the registry has no fallback |
| Per-call deadline | 300 s | process group terminated |
| Active execution | 420 s (+ up to 60 s waiting for the permit) | scheduler, then cancel and confirm |
| Cancel confirmation | 45 s after the first signal | harness; unconfirmed fails loudly |
| Server start | 90 s | harness |

**Cancellation and cleanup:** Ctrl-C once = cancel the run over HTTP, wait for the owned process group to be gone and the permit released, stop the server; Ctrl-C twice = SIGKILL the owned groups and SIGTERM the smoke server, print what is unconfirmed. The command keeps the server up if a provider process cannot be confirmed dead. The private home is deleted after the call in every path. `kill -9` of the harness cannot be handled.

**Expected evidence for `REVIEW_PENDING`:** the command prints `RESULT: task at REVIEW_PENDING, verifier passed, git integrity intact, no owned process left. Nothing was integrated.` and exits 0 only if all hold: task `REVIEW_PENDING`, 1 claim, 0 requeues; lifecycle `BACKLOG > READY > CLAIMED > CODING > VERIFYING > REVIEW_PENDING`; `providerInvocations: 1`, refused `0`, one spawned group, gone; server exited 0; verifier `go test` exit 0; diff of one line in `smoke/double.go`; `commentsKept: [true, true]`; no forbidden files; telemetry `gemini`, model as reported, cost and quota `UNKNOWN`. Report: `.workdir/m8.2-smoke/<timestamp>/report.json` with `server/provider-ledger.jsonl`, `server/server.log`, `scheduler.db`, `artifacts/`. Anything other than `REVIEW_PENDING` (including a fail-closed refusal from section 7, item 8) means: read the report, do not rerun.

## 9. Not done, deliberately, and open items

1. **No production wiring of credentials.** `defaultProviderRegistry()` registers `geminiEntry()` with its default config, which forwards no credential variable. A Gemini task through the long-running `npm run dev` server would stop at exit 41. Reading `AGENTIC_GEMINI_PASS_ENV` / `AGENTIC_GEMINI_MODEL` there is a few lines, left out because it would be silent production enablement and was not asked for. The smoke server passes its config explicitly.
2. **No automatic routing, no retry, no cloud fallback, no dashboard, no overnight automation, no bypass of sandbox or approvals** (as instructed). `--skip-trust` is the single trust grant, discussed in finding 3.
3. **Duplication with `codex.ts`:** the post-run handling (stay pending until the process group is gone, deadline vs cancel, HEAD check, redaction) is copied, not shared, to leave the verified Codex adapter untouched. Worth extracting when a third CLI arrives.
4. **Unrelated working-tree changes were preserved and not committed:** ` M .gitignore`, `?? tests/evaluation/`.
