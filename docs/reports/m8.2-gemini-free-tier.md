## 1. What the installed CLI (0.63.0) does with a model name

Read from its bundled code, then observed on the wire.

| Question | Finding |
| --- | --- |
| Exact id handling | A name that is not an alias or a known id passes through unchanged. `gemini-2.5-flash-lite` is such a name: it reached the API as `gemini-2.5-flash-lite`. |
| Aliases and silent remapping | `flash` and `flash-lite` are aliases. With an API key the CLI rewrites `gemini-3.5-flash` (and the `flash` alias) to **`gemini-3.8-flash`**, and `flash-lite` to **`gemini-3.5-flash-lite`**, because for API-key auth it treats the latest generation as launched. Observed: pins of `flash-lite` and `gemini-3.5-flash` produced requests for those other models. |
| Experimental dynamic model configuration | `experimental.dynamicModelConfiguration` defaults to off; the adapter now sets it off explicitly. |
| Fallback | For the CLI's own `flash-lite` it builds a **silent chain: flash-lite, then flash, then `gemini-2.5-pro`**. For an explicit `gemini-2.5-flash-lite` it builds a single-model chain with no fallback. Observed: a 404 and a 429 from the API did not make it ask for any other model. |
| Auxiliary models | The CLI defines about a dozen internal helpers that **name their own models and ignore `--model`**: classifier and prompt-completion (flash-lite alias), edit corrector and fixer, summarizers, web search/fetch (`gemini-3-flash-preview`), loop detection (`gemini-3-flash-preview`) and its double check (**`gemini-3-pro-preview`**), next-speaker check, context snapshotter, history summarizer, chat compression (chosen per main model). |
| Which can fire in this run | Normally none: next-speaker check, edit correction, auto-memory, context management and the conservative safety checker are off by default (the adapter pins the first two off explicitly); web tools and shell are denied; the loop-detection LLM check starts after 30 turns and the cap is 8; compression starts at 50% of the context window. One was observed firing when the safeguards were removed (section 3, ablation): a web search made a request for `gemini-3-flash-preview`. |
| Sub-agents | `invoke_agent` is denied by the admin policy and is not in the tool list the model sees. |

So the CLI cannot guarantee the model constraint by itself: the helper models are fixed by the CLI, not by `--model`, and the alias rewriting is silent. What stops them is configuration plus the guard below.

## 2. The guard (new, small, outside the provider architecture)

`tests/provider-smoke/gemini-model-guard.ts`, started and stopped by the smoke command. The adapter gets one new option, `apiBaseUrl` (loopback only), which makes the CLI talk to the guard instead of Google and selects `gemini-api-key` auth in the private settings.

- Forwards **only** `POST /v1beta/models/gemini-2.5-flash-lite:{streamGenerateContent|generateContent|countTokens}` to `generativelanguage.googleapis.com`. Any other model, alias, path, API version, method or percent-encoded trick gets a local 403 and **never leaves the machine**. Nothing is ever substituted.
- Forwards at most **12** requests; the 13th gets a local 429.
- **Trips on the first upstream 4xx** (404, 429, 401, 403, 400): that request is forwarded once, every later request is answered locally with a non-retryable 403 naming the original status. A 429 otherwise keeps the CLI retrying for minutes; with the trip the run ended in 9.7 s in the stub test. 5xx does not trip it.
- Records only method, model id, decision and status. It never stores headers (the key travels in one), bodies (the task) or responses. Loopback only; `stop()` releases the port and aborts in-flight upstream requests; a CLI that disconnects aborts its upstream request.
- The smoke is **clean only if** the CLI asked for nothing but the pinned model, nothing was blocked, the API never refused, and at least one request was forwarded. `model-guard-report.json` is written next to `report.json`.

Runtime guards in the command (all refuse before anything starts): model must be exactly `gemini-2.5-flash-lite` (every alias, every other id, case or whitespace variants, and unset are refused; nothing is defaulted); exactly one forwarded variable, `GEMINI_API_KEY` or `GOOGLE_API_KEY` (Vertex, project, location and credential-file variables are refused, since they select billed Google Cloud paths); plus the earlier opt-in, allow-list, no-arguments and key-presence checks.

## 5. Free Tier safeguards (operator)

1. **Confirm the key's project has no paid billing.** The runtime cannot see this. In AI Studio's API keys page find the key (match its last four characters, which you can print with `printf 'key ends ...%s (%d chars)\n' "${GEMINI_API_KEY: -4}" "${#GEMINI_API_KEY}"`), then on the Projects page confirm the project is on the **Free** tier with no billing account linked. A key from a billing-enabled project would make this a paid run; the guard cannot tell the difference.
2. **Free Tier access and limits are per project.** The pricing page lists `gemini-2.5-flash-lite` as free of charge, but the models page says the 2.5 models "are limited to users who have used them in the past". **Access cannot be assumed**; a 404 on the first request is a plausible outcome for a new project.
3. **A 404, 429 or any quota or access failure ends the experiment.** The guard trips on the first one, the run ends, and the command prints `STOP`. Do not switch model, do not switch project, do not add billing, do not retry.
4. **No paid-project fallback and no automatic rerun.** The command runs once and does not loop; the registry has no fallback. If the result is anything other than `REVIEW_PENDING` with a clean guard report, read `report.json` and `model-guard-report.json` and stop.
5. Free-tier content may be used to improve Google's products. The content is the synthetic fixture.

## 6. Remaining model-routing limitations

- The guard enforces the model **per request**, at the loopback address the CLI is told to use. A process that ignored `GOOGLE_GEMINI_BASE_URL` and talked to Google directly would bypass it. The CLI honours the variable (observed on every request), and its environment is built by allowlist, but this is an argument about the CLI's code, not an OS-level network block. Seatbelt here leaves the network open.
- The guard cannot tell a free key from a paid one (section 5.1).
- Not verified against the real API: that it accepts this request shape for this model with this key; the response format the guard streams through. The guard passes responses through unmodified and was tested with an SSE-style stub only.
- Internal CLI retries remain: a 5xx makes the CLI retry (up to 10 attempts per request, 5-30 s back-off) within the 12-request ceiling and the 300 s deadline. 4xx ends it at once.
- Thinking tokens versus `maxOutputTokens` accounting is unknown, but on the Free Tier there is no charge either way; only quota is affected.
- All the earlier limitations stand (task text visible in the process list, live Seatbelt confinement unobserved, real-binary signal cancellation untested, `kill -9` of the harness leaves a run directory in `$TMPDIR`).
