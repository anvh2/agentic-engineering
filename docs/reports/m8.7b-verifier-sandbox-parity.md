# M8.7B: verifier sandbox parity

**Result: implemented and verified locally.** Local stub and deterministic tests only; no cloud call, no paid Codex call; no real credential read (markers are random strings this work wrote). Nothing pushed.

## 1. Audit: the verifier's actual boundary

Who runs worker-written code through `runSandboxedCommand`: the in-run verifier and formatter (`coding-task-runner`: `gofmt`, the contract's `go test` / `npx`), integration verification (`integrate.ts`), the lifecycle's review, integration and acceptance runs (`sandboxRunner`), and the local worker's own tools (`go test`, `gofmt`, `npx jest|prettier`).

Before M8.7B the boundary was `(allow default)` plus `deny network*`, write confinement, and a hand-written list of about a dozen credential paths:

| Gap | Evidence |
| --- | --- |
| **Reads were open**: any file under the home directory not on the list, other tasks' worktrees and artifacts, the oracle | M8.6 proved it end to end: worker-written code run by the verifier read the oracle (the probe panicked and the task could not pass) whenever the harness did not deny it |
| **Mach services were open**: pasteboard, Keychain (`securityd`), preferences daemons, reachable by exec'ing `pbpaste`, `security`, `defaults` from test code | sandbox log of the new profile shows exactly these lookups denied |
| **Environment**: `PATH` (with user directories), real `HOME`, `USER`, `LOGNAME`, `GOPATH` passed through | |
| **Output channel**: the last 2000 characters of raw verifier output went, unredacted, into the next attempt's prompt (`previousFailure`) and into REPAIR feedback; for Codex that is a cloud provider | `coding-task-runner.ts` |

## 2. Implementation

**`src/runtime/sandbox/sandbox.ts`: a `deny default` profile with a read allow-list.** Modeled on the reference list in Codex's own seatbelt policy (process exec/fork, same-sandbox signals, a short sysctl list, one Mach service for user-info lookup).

- **Reads**: system pieces a toolchain starts with (`/usr/{bin,lib,libexec,share}`, `/bin`, `/System`, `/dev`, `/Library/Apple`, time-zone data); the executable's own toolchain (`toolchain.ts`: package root, GOROOT, for Go the module cache); the task root; the private temp dir; paths a trusted caller adds. `stat()` still answers, so existence and size are observable; contents and directory listings are not. The old credential/`.env`/oracle deny rules stay underneath and win over every allow.
- **Writes**: unchanged and re-verified: the root and the private temp dir only; `.git` and `node_modules` of the root stay read-only.
- **Mach**: only user-info lookup. Pasteboard, Keychain, preferences, notification and analytics services are closed.
- **Environment**: locale and terminal only, a `PATH` of the toolchain and system directories, `HOME` and `TMPDIR` = the private temp dir, `GOPATH` inside it, `GOFLAGS=-buildvcs=false` (a worktree's git directory is unreadable), Go telemetry and downloads off. No user name, no real home path. The Go module cache is reached through a private alias in the temp dir, so its home-directory path never appears in the environment or in error output.
- **Fail closed**: the self-test now proves, with a marker that shows the probe actually ran, that a read inside the root works, a write outside is refused and **a read outside the allow-list is refused**. A "sandbox" that confines writes but lets reads through makes the sandbox report itself unavailable and nothing runs (tested; the test also exposed that the first version of the probe could pass vacuously if its read never executed, which is fixed).
- **`src/runtime/sandbox/toolchain.ts`**: path helpers and toolchain discovery, now shared with the Codex isolation (`codex-isolation.ts` imports them). Never inside or above the home directory, never `/opt/homebrew`, `/usr/local`, `/Users`... as a whole.

**Output channel (`src/runtime/execution/worker-feedback.ts`)**: before verifier output reaches a worker it is stripped of terminal escapes and control characters, redacted for token shapes and secret-named environment values, and rewritten so host identity does not travel: repository path `<repo>`, temp `<tmp>`, home `<home>`, user name `<user>`, host name `<host>`, any other absolute path into a user, volume, Homebrew or system location `<host-path>`. Applied to the in-claim retry prompt and to the lifecycle's REPAIR feedback. The local record and trace keep the raw output.

**Gates**: the real-run command runs a verifier preflight (`verifierSandboxProblems`) and the Mastra server runs it together with the Codex canary before accepting work; either failing refuses to start.

## 6. Operator-supplied read paths (JS linked dependencies): kept fail-closed

Read permission is **never derived from the worktree**. A worker controls its symlinks; a `node_modules` link it could repoint would otherwise grant arbitrary reads. The only routes are `options.readAllow` and `AGENTIC_SANDBOX_READ_ALLOW`, both from trusted code or the operator. Confirmed by test:

- a path is judged by where it **resolves**: a symlink to the home directory, a symlink to the directory above it, a symlink to `/usr`, and `..` segments that climb to the home directory are all refused (through the option and through the environment variable);
- an allowed symlink grants its target, not the link, and not the target's siblings;
- a symlink **inside** an allowed directory that points at a secret does not open the secret;
- a `node_modules` symlink the worker leaves in the worktree grants nothing, even alongside a legitimately allowed dependency path; without the operator's allow the trusted directory stays closed (linked JS dependencies fail closed);
- relative paths, quotes, backslashes and control characters are refused.

No gap was found (one failure in these tests was a bug in the test's `..` arithmetic).

**Limitation**: a JS task whose dependencies are linked from outside the worktree (`linkPaths`) fails in the verifier until the operator sets `AGENTIC_SANDBOX_READ_ALLOW` to the real directory. The Go objective is unaffected.

**Future work, not built** (documented in `docs/architecture/runtime.md`): a trusted execution manifest from the scheduler to the workflow and the lifecycle runners: at claim time the scheduler, which already knows the source repository and `batch.linkPaths`, records `{taskId, claimEpoch, readAllow: [canonical paths], hash}`; the verifier accepts `readAllow` only from a manifest matching that record and re-validates every path under the rules above.

## 7. Remaining exposure

1. **Metadata**: existence, size and modification time of any path are observable; contents and listings are not.
2. **Host name** (and CPU, OS version): readable by verified code (node's `os` needs `uname`); scrubbed from what a worker is *shown*, not hidden from the code.
3. **The scrubber is pattern-based.** It removes host identity in plain form; deliberately encoded output (base64 of a host name) passes. Credentials and unrelated files are protected by the allow-list, not by the scrubber.
4. **Go module cache** is readable (third-party and, if fetched, private module source; never the parent GOPATH). **Homebrew package directories** are readable for non-Go executables (installed package names and versions; not `etc` or `var`, except node's OpenSSL config).
5. **Output that is not feedback**: worker code can still write readable-but-non-secret facts into files it is allowed to create; side-effect detection rejects changes outside the allowed files, not facts inside them.
6. The self-test runs once per process; macOS `sandbox-exec` only.
7. Everything the Codex worker reads still goes to the provider (M8.7A).
