# M8.2 Gemini: final GO gate for one real smoke

> **Superseded by `m8.2-gemini-free-tier.md`** (operator decision: Free Tier only, exactly `gemini-2.5-flash-lite`, with a wire-level request guard). The model, command and cost sections below no longer apply; the findings about aliases, ceilings and Google's controls still do.

**Recommendation: GO, conditional on the operator accepting the risks in section 8 and choosing a cost-control option in section 3.** Effective model: **`gemini-3.8-flash`**. Nothing was executed against a Google service. This session made no Gemini or Codex call; the only network contact was Google's public documentation pages.

The user's $1 figure is a target, not a limit anyone enforces. What the runtime enforces is a computed worst case of about **$0.6** on this model at current prices, which holds only if the assumption in section 3 does; Google-side controls that can make $1 a real ceiling are in section 3.

## 1. Effective model

The `AGENTIC_GEMINI_MODEL=flash` suggested in the last report was wrong. Observed on the wire (real CLI 0.63.0 through the real adapter, API-key auth, local stub, no Google contact):

| Requested | Model id actually sent |
| --- | --- |
| `flash` | **`gemini-3.8-flash`** (the CLI's own docs imply 2.5; its code says otherwise) |
| `gemini-3.5-flash` | `gemini-3.8-flash` (silently promoted) |
| `gemini-3.8-flash` | `gemini-3.8-flash` |
| `gemini-3.5-flash-lite` | `gemini-3.5-flash-lite` |
| `gemini-2.5-flash` | `gemini-2.5-flash` |

Why: for API-key auth the CLI treats the "latest flash" as launched, so the alias and two named models are rewritten to it. A pin that can change under you has no knowable price, so **the smoke command now refuses an alias or a promotable name** (`flash pro auto flash-lite gemini-3.5-flash gemini-3-flash-preview`) and refuses an unset model. Use an exact id.

Choice: **`gemini-3.8-flash`**. Google's [models page](https://ai.google.dev/gemini-api/docs/models) lists it "Stable (new)" with no shutdown date. Alternatives: `gemini-3.5-flash-lite` (stable, cheaper, exact, but weaker at tool use); `gemini-2.5-flash` (cheapest worst case because the CLI caps its thinking, but the models page says the 2.5 models "are limited to users who have used them in the past", so a new project may be refused). Whether *your* key can call `gemini-3.8-flash` is **UNKNOWN** until the run: the only way to check is a request to Google.

Prices ([pricing page](https://ai.google.dev/gemini-api/docs/pricing), per 1M tokens): `gemini-3.8-flash` $0.75 in / $3.75 out (including thinking) **through 31 Dec 2026**, then $1.50 / $7.50; free tier available. `gemini-3.5-flash-lite` $0.30 / $2.50. `gemini-2.5-flash` $0.30 / $2.50.

## 2. What the runtime now enforces (verified on the real CLI against the stub)

Two small, tested changes since the last report (`GeminiConfig.maxTurns`, `GeminiConfig.maxOutputTokens`, and the model guard above):

| Ceiling | Value | Evidence |
| --- | --- | --- |
| Model turns per invocation | **8** | Endless-tool-call stub: exactly 8 requests, then exit 53, task failed, no retry. |
| Generated tokens per request | **16,384** | `maxOutputTokens: 16384` present in every request body, attached to the exact model name via the private settings. |
| CLI invocations | 1 | server-side cap; a second is refused before it starts |
| Wall clock for the call | 300 s | process group SIGTERM then SIGKILL; real CLI killed this way in the retry runs |
| Retries / fallback / other providers | none | descriptor limits; no fallback in the registry |

Not capped: the CLI's own API-level retries, thinking tokens *if* the API counts them separately from `maxOutputTokens`, and any Google-side billing.

## 3. Quota and cost controls

Google's documents ([rate limits](https://ai.google.dev/gemini-api/docs/rate-limits), [billing](https://ai.google.dev/gemini-api/docs/billing), [Cloud Billing spend caps](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps)) say:

| Control | Hard limit? | Notes |
| --- | --- | --- |
| **Free tier, project with no billing account linked** | **Yes, $0 by construction** | Nothing can be charged. `gemini-3.8-flash` is listed free of charge. Costs: low rate limits (per project: RPM, TPM, RPD; exceeding returns 429, which the runtime treats as a failure and does not retry), and **free-tier content is used to improve Google's products** (acceptable: the content is a synthetic fixture). |
| **Prepay credits** | Yes, in effect | "When the balance reaches $0, all API keys in all projects linked to that billing account will stop working." Buy $2-5, auto-reload off. Caveat: it stops every key on that billing account, so use a dedicated account if you can. Availability in your region: UNKNOWN. |
| Gemini project spend cap | **No, not reliably** | Docs: "experimental and limited in scope", overages possible from processing delay. |
| Cloud Billing spend-cap budget (one project, one service, monthly) | Enforced but lagging | Based on estimated gross cost; per project and per service; monthly period. Not an instant $1 stop. |
| Budget alerts | **No** | Notification only. |
| Tier safeguards | Not at $1 | Tier 1: $10 per rolling 10 minutes; billing-tier cap $250 per month. |
| Lower the project's request quota yourself | **UNCONFIRMED** | I found no Google page saying a Gemini API consumer can lower its own per-model quota (forum posts show Console quota pages exist, with unclear bounds). Do not rely on it. |

**Recommended: the free-tier option** (dedicated new AI Studio project, no billing linked). It makes the dollar risk zero and leaves only quota failures, which fail closed. If it cannot run the model (429 or 404), the second choice is prepay with $2-5, not a postpay account with a spend cap.

Worst case on a paid account at `gemini-3.8-flash` (promotional price), my estimate: input about 10k tokens on turn 1 growing 1.5k per turn, so about 122k over 8 turns, about $0.09; output at most 8 x 16,384 = 131k tokens, about $0.49; total about **$0.58**. At the post-promotion price about $1.2, which does not apply before 2027. Typical run, 2-3 turns: about 30k input and 3k output, roughly **$0.03**. Assumption to accept: `maxOutputTokens` bounds the *total* generated tokens including thinking; Google's page does not say so in the parts I read. If thinking were additional, the worst case is higher and unbounded by us (the CLI sends `thinkingLevel: HIGH` for this model and no thinking budget).

## 4. Does the key belong to the intended project?

**Cannot be confirmed from here, by design.** There is no way to ask Google which project a key belongs to without a request carrying the key, and I was told to make none and not to read the secret. In this session's environment neither `GEMINI_API_KEY` nor `GOOGLE_API_KEY` is set (checked by name only), so nothing was read. Google's billing page says keys "have no independent billing settings" and are tied to the project they were created in; AI Studio's API keys page lists each key with its project, and the Projects page shows that project's tier and billing plan.

Check it yourself, without showing the secret:

```sh
printf 'key ends ...%s (%d chars)\n' "${GEMINI_API_KEY: -4}" "${#GEMINI_API_KEY}"
```

Match the last four characters to the key listed in AI Studio, then confirm on its Projects page: the dedicated project, **Free** tier (or Prepay with the small balance), and no other billing account linked.

## 5. The smoke cannot do more than one task on a fixed fixture

Verified in code and by tests (64 Gemini tests, plus 4 live refusals of the command):

| Question | Answer |
| --- | --- |
| Real repositories | Not reachable. The command takes no arguments; the only task is the generated `smoke-double` fixture in a new directory under `.workdir/`; the server it starts is its own (own port, own storage), never your `:4111` one. |
| More invocations | No. Server-side cap of 1 (a second `gemini` start is refused and counted), 1 claim, no requeue; a lease expiry on a non-default provider goes to `RUNTIME_FAILURE`. |
| Automatic fallback | No. The registry has none; an unavailable Gemini fails the task (tested with Codex registered and allowed: never started). |
| Task retries | No. 0 automatic runtime retries; the runner's second *coding* attempt would need a second invocation, which the cap refuses. |
| Wrong provider or task | The allow-list handed to both processes is exactly `gemini:smoke-double`, whatever you export. |

## 6. Logging

Checked on the last smoke's evidence (names and counts only): the persisted files (`report.json`, `server.log`, ledger, `trace.jsonl`, `attempts.json`) contain no prompt text and no "You are a coding worker"; `server.log` is three lines; the artifacts do include the task contract and the final diff, which for this run are the synthetic fixture. The key appears nowhere: not on any command line, not in the settings, policy, request bodies or evidence (section 2 of the preflight report), and the harness prints credential *names* only. Retained deliberately: the model's request bodies are not stored anywhere by us. The CLI's chat transcript lives in the private run directory and is removed at the end (a `kill -9` of the harness would leave it in `$TMPDIR/agentic-gemini-*`; check afterwards).

## 7. Maximum runtime, internal retries, remaining billing risk

| | |
| --- | --- |
| Expected | 20-120 s end to end (server start a few seconds, one to three model turns with HIGH thinking, `go test` a few seconds). |
| Hard maximum | about **10.5 minutes**: server start 90 s + permit wait 60 s + active execution 420 s + cancel confirmation 45 s + shutdown. The model call itself ends at 300 s. |
| Internal retries | Not counted by the runtime. The CLI retries a failing request up to **10 times with 5-30 s back-off**; against an always-503 or always-429 stub it made 5 attempts in 90 s, so about 9-10 in 300 s. Failed 429/5xx requests are normally not billed (UNKNOWN for certain). Each *successful* turn is one billed request, at most 8. |
| Billing risk left | The $ ceiling is only as hard as the Google-side control chosen in section 3. With a free-tier project it is zero. With a paid project it is the computed $0.6 bound plus the thinking-token assumption, plus lag in whatever cap you set. |

## 8. Remaining risks requiring operator acceptance

1. **Billing is not hard-capped by the runtime.** Accept the Google-side option (free tier recommended).
2. **Thinking tokens versus `maxOutputTokens`** is an assumption (section 3).
3. **Model availability for your key is unknown** until the run; `gemini-3.8-flash` pricing is promotional until 31 Dec 2026.
4. **Free-tier content may be used to improve Google's products.** Fixture only.
5. **Task text and the fixture's file contents are visible in the process list** to local users for the run's duration (preflight section 4).
6. **Unproven in a real run**, each failing closed after at most one invocation: the CLI completing under Seatbelt with a private home; `--skip-trust` enabling edits headless; the real API accepting this request; the real stream format; live OS confinement (never observed denying anything; tool-level checks stop every escape first).
7. **Real-binary cancellation by signal** is untested; deadline termination of the real CLI was tested.
8. **A hard kill of the harness** leaves a private run directory with a chat transcript in `$TMPDIR`.
9. The CLI's own outbound contact other than the model API was sampled, not blocked (only the stub was ever seen); telemetry is switched off in its settings and environment.

## 9. Exact command

In your own terminal, with the dedicated project's key (never typed into the command):

```sh
export GEMINI_API_KEY=...      # key of the dedicated project; then run the printf check in section 4

cd /Users/anvh/go/src/github.com/anvh2/agentic-engineering && \
AGENTIC_REAL_PROVIDER_SMOKE=gemini-http \
AGENTIC_ALLOW_PROVIDERS=gemini:smoke-double \
AGENTIC_GEMINI_PASS_ENV=GEMINI_API_KEY \
AGENTIC_GEMINI_MODEL=gemini-3.8-flash \
npm run smoke:gemini-http
```

It prints the model, the 8-turn and 16,384-token ceilings and the bounds before it starts. Run it once; if the result is not `REVIEW_PENDING`, read `.workdir/m8.2-smoke/<timestamp>/report.json` and do not rerun. Afterwards: the integrity checks in section 8 of `m8.2-gemini-adapter.md` and `ls -d "$TMPDIR"/agentic-gemini-*` (expect nothing).
