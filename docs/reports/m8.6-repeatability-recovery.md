# M8.6: repeatability, failure recovery and oracle read isolation

**Verdict: ACCEPTED** for what it covers: mock and local verification only. No cloud inference and no paid Codex call was made in M8.6. The M8.5 evidence and fixture were not modified or rerun (hashes re-checked, section 9). Nothing pushed.

## 1. Findings that changed the code

| # | Finding (how it was shown) | Fix |
| --- | --- | --- |
| 1 | **The M8.5 oracle was readable by the Codex worker.** Under `--sandbox workspace-write`, a model-issued `cat` returned the oracle's text; only writes are confined. Shown with the real `codex exec` against a local stub model, not inferred. M8.5's evidence does not show that it *was* read | `CodexConfig.denyReadPaths`: a filesystem permission profile (read everywhere but the listed paths; write only the worktree and temp dirs; `.git` and `.codex` read-only) |
| 2 | **`--sandbox` silently overrides a permission profile** (codex-cli 0.161.0): with both, the profile was ignored and the oracle stayed readable, with no error | The adapter omits `--sandbox` when a deny list is set, and a canary proves the result against the real binary |
| 3 | **The verifier sandbox could read the oracle** too: it denies credentials and `.env` only, and it runs worker-written Go code | `denyRead` option and `AGENTIC_SANDBOX_DENY_READ`, passed to the Mastra server and to the lifecycle runner; fails closed on a bad or self-containing path |
| 4 | **The invocation budget was in memory**, so a restarted server would start from zero | One exclusive-create file per slot beside the ledger; survives restarts and overlapping servers |
| 5 | **The lifecycle driver lock was re-entrant per owner** and the owner was `actor:pid`, so two drivers in one process both ran the objective | Owner is unique per call |
| 6 | A **crashed server leaves a model-permit lease row** (until the next admission reaps it) and **orphans the Codex process group** | Cleanup finds orphans through the ledger and kills them; a permit probe takes and releases the Codex permit to prove it is free |

Parity check for finding 1's fix: with `.git` and `.codex` read-only under the project root the profile matches `workspace-write` on every probe (writes to the worktree and temp OK; `.git`, `.git/hooks`, `.codex` and outside paths denied; `go vet` works). Without those two entries, `.git/hooks` was writable: that gap was found and closed before the code was written.

## 2. Repeatability

Three runs on three fresh disposable repositories (fake Codex, same path as the real run): all `ACCEPTED`, identical signature (task states, claims 1/1, 2 invocations, oracle spec hash, criteria hash, **candidate tree id and base tree id**, exit codes `[0,0]` / `[0,1]`), with distinct repositories, server pids and addresses, Mastra run ids and integration commits. Re-driving a finished objective claims nothing, dispatches nothing, writes no task event and returns the same verdict; a second concurrent driver gets `driver_locked`.

## 4. Oracle read isolation: status

| Layer | Enforced by | Proof |
| --- | --- | --- |
| Codex worker | `denyReadPaths` profile built from validated, symlink-resolved absolute paths; unit-tested argument construction, refusal of unquotable paths, fail-closed when the CLI lacks `--config`, refusal when the worktree overlaps a denied path | **Real `codex exec` against a local stub model**: control reads the canary; with the adapter's own arguments it gets "Operation not permitted"; the worktree stays writable; outside writes and `.git` writes stay blocked |
| Verifier / review / integration / acceptance sandbox | `denyRead` and `AGENTIC_SANDBOX_DENY_READ` | sandbox tests (cat, ls, symlink, relative path, Go test-time read, fail-closed); end to end: worker-written code that probes for the oracle **panics the verifier without isolation and finds nothing with it** |
| What is denied | the oracle directory (moved beside, not inside, the run directory), `scheduler.db*` (holds the hidden task tests), the harness source (embeds the fixture oracle), the enclosing checkout's `.git`, the legacy M8.5 evidence | harness test asserts the list, and that the server's Codex config received the same list |
| Preflight | `preflightProblems` runs the canary before any real run | refuses (`M8_5_BLOCKED_BY_PREFLIGHT`) if a read is not denied, the worktree is not writable, or a write outside / into `.git` is not blocked |

Isolation is on by default in the harness. The fixture, the oracle text and the criteria are unchanged.

## 5. Telemetry

Reported per task and in total: provider, model, input and output tokens, inference latency, active time, cost. Anything nobody reported is `UNKNOWN`, never 0 and never an estimate, and one unknown makes a total unknown. Observed on the real CLI's `--json` stream: it carries token counts (plus cached and reasoning tokens, not yet captured) but **no model name and no cost**. Model identity is therefore the operator's pin (`AGENTIC_CODEX_MODEL`) or `UNKNOWN`; cost is `UNKNOWN` unless a price source is added.

## 7. Remaining risks

- **Isolation was proved with the real `codex` binary and a stub model, not with a real model through the full Mastra path.** The profile is a CLI behavior that already changed our assumptions once (finding 2); the preflight canary exists for that, but it exercises the `exec_command` tool only. Other tools (image viewing, MCP) were not probed; with `--ignore-user-config` none are configured.
- **The worker can still read everything else the user can read**, including `~/.codex/auth.json` and other home files. Only listed paths are denied.
- The oracle's secrecy for the fixture also depends on the denied harness source and `.git`; a future oracle should live outside any repository the worker can name.
- Time to a terminal state after a server crash is bounded by the task timeout (25 s in the test, 420 s in production), not by crash detection.
- A crash between taking a budget slot and spawning burns the slot: fail-safe, but it can cost an invocation.
- The lock fix changes `src/lead/lifecycle/driver.ts` and the adapter gained a feature (`src/workers/providers/codex.ts`); both are tested, both were needed, and both go beyond "tests only".
- Failure injection covers one provider mode per scenario with a deterministic fake; real-model variability (partial edits, slow starts) is untested.
- macOS only (`sandbox-exec`).
