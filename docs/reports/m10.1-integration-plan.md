## Dependency and security review of the carried code

- **Meeting participants** only return a message; they have no tools and cannot decide, authorise or change tasks. A non-default provider needs the operator allow-list (`AGENTIC_ALLOW_PROVIDERS` / `--allow-provider`), checked at `open` and again by every `run`. Provider-backed turns run in an empty scratch repo through the existing provider adapters (sandbox, environment allow-list, process-group cancel).
- **Network**: one `fetch` to `OLLAMA_BASE_URL` (default `localhost:11434`), the same variable `coding-worker.ts` and `providers/ollama.ts` already honour, so no new class of exposure. The reply's model name must equal the pinned one.
- **Process execution**: `execFileSync('git', …)` with fixed argv and no shell, in a scratch directory.
- **Path handling**: ids are validated by `idSchema` (`[A-Za-z0-9._:-]`, no slash), so session ids cannot traverse out of the meetings directory.
- **Fault points**: no code path enables them in production; the plan reaches the Mastra child only through an explicit `faultEnv`.
- **New dependencies**: none (`package.json` gains one script, `reliability`).

## Order of work

M10 shows what goes wrong when the same session writes the acceptance criteria and then the code. So the oracle is written **first**, and the order differs from the phase numbering:

1. Baseline on unmodified `main`: typecheck and full regression (known starting point, including the F2 collision).
2. Phase 4 first: corrected oracle v3 for F2 (plus scheduler acceptance and objective-scoped promotion), pinned by hash, negative-controlled on `c77ffdd`, reviewed by a separate fresh-context reviewer that sees no implementation.
3. Phases 1 to 3: F2 run-scoped permit ownership, acceptance truth, objective-scoped promotion.
4. Phase 5: carry the safe M10 components by file, with the scenario repair, not by cherry-picking commits.
5. Phase 6 verification and Phase 7 report.

Deliberately out of scope: M11 supervisor, M12 provider pool, M13 configuration UI, any push or merge, any write to the operational scheduler database.
