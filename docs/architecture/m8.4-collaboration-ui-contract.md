# Collaboration viewer and Core B

Status: **CONNECTED (M9)**. The Discussions and Meetings views read Core B's persisted collaboration store (`src/runtime/collaboration`, `collab_events` in the scheduler database) through a read-only Gateway adapter, `src/integrations/control-center/collaboration-adapter.ts`. No second store, scheduler, coordinator or event schema was added; the Gateway never writes.

| Endpoint (embedded; standalone uses `/api/v1`) | Returns |
| --- | --- |
| `GET /control-center/v1/collaboration` | The whole view: every thread with its messages, every meeting session with its record, and the feed `cursor` it is consistent with |
| `GET /control-center/v1/collaboration/threads/:id` | One thread and its sessions (404 if unknown, 400 if not a Core B id) |
| `GET /control-center/v1/collaboration/sessions/:id` | One meeting session with its record and provenance |
| `GET /control-center/v1/collaboration/events` | SSE invalidation feed; `id` is Core B's global `seq`, so `Last-Event-ID` resumes |

`availability` is `AVAILABLE` (records, possibly none), `NOT_AVAILABLE` (no database), or `CORRUPT`. CORRUPT means Core B's replay rejected the hash chain or an event, or an append-only guard (trigger or index) is missing; then no records at all are returned. Without a configured reader (unit tests), `/collaboration` stays `NOT_AVAILABLE`.

**How the adapter reads.** It opens the database `readOnly` with `query_only`, rejects a missing guard, and hands Core B's unchanged `CollaborationStore` a facade of `db`, `now` and a read transaction. The store's `CREATE ... IF NOT EXISTS` is a no-op on an existing table. Inside that one transaction it calls `collaborationOverview`, `thread()` (the hash-chain-verified replay) and `record()`.

The **presentation DTO** (`apps/control-center/src/collaboration-model.ts`) is the viewer's shape. The adapter maps Core B into it as follows:

- Message kinds are uppercased Core B kinds, and each message keeps its `seq`.
- Corrections and withdrawals stay links, so originals are never rewritten.
- Evidence references are opaque labels, not links.
- Decisions, agreements, objections, unresolved items and action items come only from the stored meeting record.
- Usage that is unreported, in flight, or belongs to a charged turn with no message is `null` (UNKNOWN).
- Identities whose persisted `provider` is `fake` mark a thread `synthetic`, and the UI labels it "DETERMINISTIC FAKE PARTICIPANTS ... Not live model output".

The test-only fixture `apps/control-center/__testing__/collaboration-fixture.ts` is never imported by production.

## Original requirements (all met by Core B's records)

Provide an exported side-effect-free snapshot reader with stable thread, message, meeting, round, participant and invocation IDs. Reads must not coordinate meetings, start agents or consume model permits. Please include an authoritative revision/cursor for subsequent SSE integration, and distinguish missing data from empty reported collections.

| Presentation data | Required authoritative source |
| --- | --- |
| Thread title, objective/task IDs | Persisted thread metadata; task/objective links must use scheduler IDs |
| Participants and roles | Authored identities, never inferred online presence |
| Message ID, author, UTC timestamp, type, public collaboration text | Explicit agent-authored collaboration messages, excluding private reasoning, prompts, credentials and raw provider output |
| Reply relationship, evidence URLs, invocation and trace IDs | Persisted source references; unresolved or missing references must remain visible |
| Open/resolved/unknown objection state | An explicit objection lifecycle record, not an inference from silence or a later decision |
| Meeting agenda, participants, start/end times | Persisted meeting records |
| Round progress, round/invocation limits, usage/exhaustion | Coordinator-owned counters and budgets, null when unavailable |
| Agreements, unresolved disagreements, decisions | Explicit records with original source-message IDs; the viewer never derives consensus |
| Actions, owners, follow-up state | Persisted action records plus original source-message IDs |
| Meeting usage | Reported scoped input/output tokens, completeness and source; include failed/cancelled/retried call identity to prevent duplicate aggregation |

Remaining limitations:

- **No pagination.** The snapshot returns every thread. Core B bounds a thread at 5,000 events, but not the number of threads.
- **Action follow-up state.** Core B does not record it, so it is shown as UNKNOWN.
- **No trace links.** Core B stores trace ids only when a real adapter reports them, and there is no verified Studio trace URL, so `traceUrl` stays null.

## Update and privacy behavior

The viewer replaces the complete, verified snapshot. It refreshes on each collaboration SSE frame, and on every stream reconnect or reset, with a five-second serial poll as a fallback. It never appends SSE deltas or accumulates token counts. SSE frames carry only `seq`, `threadId`, `type` and `at`, never message bodies. A client resumes with `Last-Event-ID`, and a non-numeric cursor or one beyond the store gets `reset`. Duplicate message IDs are collapsed within their owning thread and ordered by timestamp, with an ID tie-breaker. Disconnects remove displayed collaboration records until recovery. Existing scheduler SSE remains unchanged in meaning and replaces activity/usage snapshots.

Zod selects only the declared presentation fields; unknown private fields are stripped. Text is rendered as plain React text, never HTML/Markdown execution. Reference links allow HTTP(S) or same-origin absolute paths only, reject credential-bearing URLs and executable protocols. This is defense in depth: the future Gateway adapter must explicitly whitelist public collaboration text, sanitize/redact source fields, validate IDs and reject hidden reasoning before serialization. A frontend schema alone does not make arbitrary Core messages safe to expose.

Do not create a parallel event store or reconstruct collaboration from model traces. Core B's store is the only source.
